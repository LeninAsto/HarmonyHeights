# Guía breve para la exposición

Duración sugerida: **6 a 8 minutos**.

La presentación interactiva completa está en `../trabajo final/presentacion.html`. Se navega con los botones, las flechas del teclado o la barra espaciadora.

## Diapositiva 1 — Problema

- Información académica dispersa.
- Registro manual de interesados.
- Experiencia visual poco clara en móviles.

**Qué decir:** “Diseñamos un micrositio para presentar la oferta académica y ordenar la captación de interesados”.

## Diapositiva 2 — Propuesta

- Academia ficticia de música y artes escénicas.
- Seis páginas conectadas por un menú responsive.
- Flujo claro: descubrir, comparar y solicitar orientación.

Muestra una captura de Inicio en escritorio y otra en móvil.

## Diapositiva 3 — UX/UI

- Jerarquía visual y CTAs.
- Paleta coherente y alto contraste.
- Navegación constante.
- Diseño adaptable.

Muestra las tarjetas de programas y el menú móvil.

## Diapositiva 4 — Tecnologías

- HTML5 semántico.
- CSS3, Flexbox y Grid.
- Bootstrap 5.
- JavaScript y manipulación DOM.
- PHP para el formulario.

**Idea simple para explicarlo:** HTML es la estructura, CSS es la apariencia, JavaScript es el comportamiento y PHP procesa el envío en el servidor.

## Diapositiva 5 — Interactividad

En vivo:

1. Abre `programas.html`.
2. Filtra por Música, Danza y Escena.
3. Reduce el ancho para enseñar el menú responsive.
4. Explica la animación al desplazarse.
5. Abre el panel de accesibilidad y activa contraste o texto grande.
6. Muestra “Volver arriba”, el mapa y el audio ambiental opcional.

## Diapositiva 6 — Formulario y backend

1. Intenta enviar campos vacíos para mostrar validación.
2. Completa datos ficticios.
3. Envía con PHP activo.
4. Enseña la nueva línea en `backend/data/solicitudes.jsonl`.

Aclara que `POST` manda datos en el cuerpo de la solicitud y que PHP vuelve a validarlos antes de guardar.

## Diapositiva 7 — Cierre

- Se resolvió la navegación y presentación institucional.
- Se organizó la oferta académica.
- Se implementó captación funcional.
- El proyecto puede crecer hacia base de datos y panel administrativo.

**Frase final sugerida:** “Harmony Heights demuestra que una solución pequeña, bien organizada y centrada en el usuario puede resolver un problema institucional real sin añadir complejidad innecesaria”.
